# Финанс — мобильное приложение (iOS/Android)

React Native (Expo) клиент к тому же backend, что и веб-версия в корне
репозитория. Использует тот же API, поэтому данные общие: операция,
добавленная в приложении на телефоне, сразу видна в браузере и наоборот.

## Быстрый старт (тестирование на своём iPhone уже сегодня, без Mac)

1. Backend должен быть запущен и доступен по сети (см. README.md в корне
   репозитория — локально по Wi-Fi или задеплоенный). Локальный `next dev`
   слушает `0.0.0.0`, так что достаточно IP компьютера в локальной сети.

2. Установите зависимости и укажите адрес backend:

   ```bash
   cd mobile
   npm install
   cp .env.example .env
   # впишите реальный адрес: http://<IP-компьютера>:3000 (не localhost —
   # с точки зрения телефона localhost это сам телефон)
   ```

3. Запустите Metro:

   ```bash
   npx expo start
   ```

4. На iPhone установите из App Store бесплатное приложение **Expo Go**,
   откройте его и отсканируйте QR-код из терминала. Приложение откроется
   прямо на телефоне — без сборки, без Xcode, без аккаунта разработчика.

   Если телефон и компьютер не в одной Wi-Fi сети (например, вы работаете в
   облачной среде), запустите `npx expo start --tunnel` — Expo создаст
   публичный адрес, доступный из любой сети.

## Путь к реальному приложению в App Store

Это уже не тестовый режим через Expo Go, а настоящая сборка .ipa.

1. **Заведите аккаунт Apple Developer Program** (99$/год, developer.apple.com) —
   без него App Store не примет приложение. Это обязательный шаг, который
   может сделать только владелец аккаунта.

2. Заведите бесплатный аккаунт на [expo.dev](https://expo.dev) и войдите:

   ```bash
   npm install -g eas-cli
   eas login
   ```

3. Убедитесь, что `.env` (или переменная окружения `EXPO_PUBLIC_API_URL` при
   сборке) указывает на **постоянный публичный адрес backend** — то, что
   пользователи будут использовать, а не локальный IP для разработки.

4. Соберите iOS-билд в облаке Expo (Mac не нужен — сборка идёт на серверах
   Expo):

   ```bash
   eas build --platform ios --profile preview
   ```

   При первом запуске `eas build` предложит создать нужные сертификаты и
   профили подписи автоматически — подтвердите привязку к вашему Apple
   Developer аккаунту.

5. Установите готовый билд на свой iPhone через TestFlight (внутреннее
   тестирование, до ревью) или соберите профиль `production` и отправьте
   в App Store:

   ```bash
   eas build --platform ios --profile production
   eas submit --platform ios
   ```

6. Заполните карточку приложения в App Store Connect (скриншоты, описание,
   политика конфиденциальности) и отправьте на ревью Apple — обычно 1–3 дня.

## Структура

```
app/(auth)/          экраны входа и регистрации
app/(tabs)/           обзор, операции, бюджеты, кошельки, ещё
app/*-form.tsx         модальные экраны добавления/редактирования
components/            переиспользуемые UI-компоненты
lib/                    API-клиент, авторизация (токен в Keychain через expo-secure-store), типы
```

## Отличия от веб-версии

Веб-приложение использует HTTP-only куку для сессии (подходит для браузера).
Мобильное приложение вместо этого получает JWT-токен при входе/регистрации
и хранит его в защищённом хранилище устройства (Keychain на iOS через
`expo-secure-store`), передавая его в заголовке `Authorization: Bearer …` —
это стандартный подход для нативных клиентов. Один и тот же backend
поддерживает оба способа одновременно.
